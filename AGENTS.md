# Working in this repository

Instructions for any agent or contributor. Read these first:

1. [Product](docs/product.md): what elaborat.ing is and for whom.
2. [Architecture](docs/architecture.md): settled decisions and open questions.
3. [Roadmap](docs/roadmap.md): what is being built now, in order.
4. [Platform notes](docs/platform-notes.md): Supabase and Cloudflare facts, with sources.
5. [Task queue](docs/tasks.md): self-contained tasks for contributors and agents.

Implemented behavior lives in code and tests. The docs above also describe
planned work: never describe something as working until it is built and tested.

## Stack

| Area | Choice |
|---|---|
| Runtime and packages | Bun 1.4 for installs, scripts and tests. Commit `bun.lock`. Pin exact versions. |
| App | Vite 8, React 19 with the React Compiler (stable Babel preset), strict TypeScript |
| Routing | TanStack Router file routes. `src/routeTree.gen.ts` is generated by the build and not committed. |
| Styling | Tailwind CSS 4 through its Vite plugin. UI primitives: shadcn/ui on Base UI (`base-nova`), added when needed. |
| Validation | Zod v4 at real external boundaries (API responses, stored browser data, URL input, config) |
| Backend | Supabase: Postgres with RLS, Auth, Realtime, Edge Functions. Supabase CLI 2.118.0 (`bunx supabase@2.118.0`). |
| Frontend hosting | Cloudflare Workers static assets, configured in `wrangler.jsonc` |
| Checks | ESLint, `tsc`, Bun tests; Playwright with axe for key journeys once there are journeys |

## Commands

```bash
bun install --frozen-lockfile
bun run dev         # local dev server
bun run build       # production build; also generates the route tree
bun run typecheck   # run after a build
bun run lint
bun run test
```

CI runs build, typecheck, lint and test on every pull request, and fails if
regenerating migrations from `supabase/schemas/` would change
`supabase/migrations/`.

## Rules

- **Canonical over clever.** Use the standard, current, documented way for each
  tool: Supabase's guides and library blocks, the official MCP SDK, standard
  OAuth, Cloudflare's documented config. If you think something needs an
  unusual approach, stop and record why in `docs/architecture.md` first.
- **Supabase is code.** Settings go in `supabase/config.toml`. The database is
  declared in `supabase/schemas/`. To change it, edit the schema files, run
  `bunx supabase@2.118.0 db schema declarative sync` to generate a migration,
  and commit both. Never hand-edit a generated migration. Never change the
  hosted project in the dashboard when a file can do it; the exceptions are
  listed under "Manual steps" in the architecture doc.
- **Every table has RLS, policies, explicit grants and a test.** Tables are not
  exposed to the Data API unless granted. Functions are executable by everyone
  by default, so revoke `execute` from `public` and `anon` before granting it.
  A policy change without a pgTAP test (in `supabase/tests/`) proving one user
  cannot see another user's data is not done.
- **Agents never permanently delete.** Enforce, and never weaken, the database
  rule that refuses permanent deletes from OAuth-client sessions (built in
  roadmap phase 1 step 1).
- **No secrets in the repository.** Only public values (the Supabase URL and
  publishable key) may appear in `VITE_` variables, because Vite ships them to
  the browser. Secrets go in Supabase or Cloudflare secret storage, or GitHub
  repository secrets.
- **Test against the cloud.** Database, auth and function changes are checked
  on a hosted Supabase project, not a local `supabase start` stack.
- **Smallest complete change.** Do what the task asks, test in proportion to
  risk, and list anything else you notice instead of fixing it.
- **Keep docs true.** If a change settles an open question or changes a
  decision, update the architecture or roadmap in the same change.
- **Plain language in user-facing text.** No em dashes in UI copy, README text
  or release notes.
